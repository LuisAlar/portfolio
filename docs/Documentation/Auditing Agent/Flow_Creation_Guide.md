# Power Automate Flow Creation Guide
**Step-by-Step Guide to Implementing the Document Review Workflow**

This guide provides a detailed, step-by-step walkthrough for building the Power Automate flow. Since the AI Agent (Eddy) is a chatbot/API engine that outputs a raw text string, the flow must clean that text, convert it into parsed JSON, and write the data into Word and Excel templates.

---

## 1. Prerequisites (SharePoint Setup)

Before building the flow, create a `/Templates` folder in your SharePoint site and save these two files in it:

### Template A: `Error_Log_Template.xlsx`
1. Create a blank Excel spreadsheet.
2. In the first row, create the following headers:
   `Category` | `Page` | `Section` | `Paragraph` | `Quoted Text` | `Rule` | `Correction` | `Explanation`
3. Select the headers and a few empty rows below them, and click **Format as Table** (choose any style).
4. In the **Table Design** tab, name the table: `FindingsTable`.
5. Save the file as `Error_Log_Template.xlsx` in your `/Templates` folder.

### Template B: `Review_Template.docx`
1. Create a blank Word document.
2. Enable the **Developer** tab (File > Options > Customize Ribbon > check "Developer").
3. Use **Plain Text Content Controls** (from the Developer tab) to create placeholders for:
   * `ReviewedContent`
   * `ReviewGaps`
   * `TopRecurringIssues`
4. Add a table with the findings. Select the data row of the table, and in the Developer tab, insert a **Repeating Section Content Control** (named `FindingsLoop`). Inside the cells of this repeating row, add plain text content controls for:
   * `Category`
   * `Page`
   * `Section`
   * `Paragraph`
   * `QuotedText`
   * `Correction`
5. Save the file as `Review_Template.docx` in your `/Templates` folder.

## 2. Comparing Architectures: Folder-First vs. Bot-First

If your company's IT policy blocks the **Execute Agent** connector in Power Automate, you have two pathways to build this:

| Feature | Architecture 1: Folder-First (HTTP-Driven) | Architecture 2: Bot-First (Copilot Plugin) |
| :--- | :--- | :--- |
| **How it starts** | User uploads a file to the `Documents for Review` SharePoint folder. | User chats with the bot (in Teams/M365) and uploads the document. |
| **How Eddy is invoked** | Flow uses the **HTTP Premium connector** to call an LLM API directly (e.g., OpenAI/Azure OpenAI). | Eddy processes the file natively in Copilot, then triggers the flow as a "Tool/Plugin". |
| **Trigger Action** | `When a file is created (properties only)` | `When an agent calls the flow` |
| **Licensing/Policy** | Requires HTTP Premium & API Keys. | Bypasses blocked "Execute Agent" connector. Uses standard connections. |
| **Cleanup Action** | Deletes the original file from the SharePoint folder. | No file to delete (document resides inside the chat session). |
| **CRUD & Templates** | Flow generates Word/Excel reports in SharePoint and emails links. | Flow generates Word/Excel reports in SharePoint and emails links. |

## 3. Option 1 Setup: Folder-First Flow (HTTP Endpoint)

Follow this setup if you want fully automated, folder-drop processing and have access to the HTTP connector or an external API endpoint for Eddy/OpenAI.

### Step 1: Trigger (Listen for uploads in a specific folder)
1. Add trigger: **When a file is created (properties only)** (SharePoint). Set Site Address and Library Name.
2. Click the three dots `...` on the trigger card and select **Settings**.
3. Under **Trigger Conditions**, click **Add** and paste:
   ```js
   @contains(triggerOutputs()?['body/{Path}'], 'Documents for Review')
   ```

### Step 2: Get File Content & Extract Text
1. Add action: **Get file content** (SharePoint) using the trigger's `Identifier`.
2. Extract the text content using **Word Online (Business) - Get properties/text** or AI Builder text extractors.

### Step 3: HTTP API Call
1. Add action: **HTTP** (Method: `POST`).
2. Input the endpoint URI (e.g., OpenAI or your custom-hosted LLM).
3. Pass the system prompt (your regulation template rules) and the document text in the JSON body.
4. Clean and parse the JSON string response (see **Section 5** below).

## 4. Option 2 Setup: Bot-First Flow (Copilot Studio Plugin)

Follow this setup if the Power Automate trigger is blocked. The flow acts as a tool for the agent: when the user asks the chatbot to review a document, the chatbot performs the analysis and then tells the flow to build the files.

### Step 1: Trigger (When an agent calls the flow)
1. In Power Automate (or Copilot Studio), create a flow and select trigger: **When an agent calls the flow** (Microsoft Copilot Studio connector).
2. Click **Add an input** and choose **Text**.
   * **Name:** `FindingsJSON`
   * **Description:** "The JSON string containing the coverage metrics and findings list generated by the agent."

### Step 2: Clean and Parse JSON
1. Add action: **Compose** (Rename to `Compose - Clean JSON`).
   * **Inputs:** Use the expression to clean any markdown markers from the input text:
     ```js
     trim(replace(replace(triggerBody()?['FindingsJSON'], '```json', ''), '```', ''))
     ```
2. Add action: **Parse JSON** (Data Operations).
   * **Content:** Select the `Outputs` of `Compose - Clean JSON`.
   * **Schema:** Paste your findings schema (refer to Section 5).

### Step 3: Generate Files and Email (Same as Option 1)
1. **Excel:** Copy the template, run an **Apply to each** loop on the parsed `findings` array, and insert rows into the spreadsheet.
2. **Word:** Populate the content controls in the Word template and save it to `/Agent Reports by Document`.
3. **Email:** Send completion emails to the User, Manager, and Owner with links to the generated documents.

### Step 4: Respond to the Agent
1. Add action: **Respond to the agent** (Microsoft Copilot Studio connector).
2. Click **Add an output** and select **Text**.
   * **Name:** `StatusMessage`
   * **Value:** `Success. The Word report and Excel log have been successfully generated and saved to SharePoint. Emails have been sent to the stakeholders.`

## 5. Schema for Parse JSON Action
Copy and paste this schema into the **Parse JSON** step for both Option 1 and Option 2:
```json
{
  "type": "object",
  "properties": {
    "coverage": {
      "type": "object",
      "properties": {
        "reviewed_content": { "type": "string" },
        "review_gaps": { "type": "array", "items": { "type": "string" } }
      }
    },
    "findings": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "category": { "type": "string" },
          "location": {
            "type": "object",
            "properties": {
              "page": { "type": "integer" },
              "section": { "type": "string" },
              "paragraph": { "type": "integer" }
              }
            },
          "quoted_text": { "type": "string" },
          "rule": { "type": "string" },
          "correction": { "type": "string" },
          "explanation": { "type": "string" }
        }
      }
    },
    "metrics": {
      "type": "object",
      "properties": {
        "acronyms": { "type": "integer" },
        "grammar": { "type": "integer" },
        "wording": { "type": "integer" },
        "tone": { "type": "integer" },
        "consistency": { "type": "integer" }
      }
    },
    "top_recurring_issues": {
      "type": "array",
      "items": { "type": "string" }
    }
  }
}
```
